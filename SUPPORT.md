# Support

## Before asking for help

1. Read the [README](README.md).
2. Check the relevant guides in [docs/](docs/README.md).
3. Search existing issues for the same error.
4. Reproduce the problem with a development account and synthetic data.

## Information to include

A useful support request includes:
- The route or command where the issue occurs.
- Expected behavior and actual behavior.
- Steps to reproduce.
- Node.js and npm versions.
- Browser and operating system, when relevant.
- A sanitized error message or GitHub Actions run link.
- Whether the issue occurs locally, in CI, or after deployment.

## Never share

Do not include:
- Clerk secret keys or session tokens.
- Gemini API keys.
- Database connection strings.
- Production database records.
- Real candidate answers or private interview content.
- Unredacted request headers or environment dumps.

## Where to report

Use GitHub Issues for reproducible bugs and feature proposals. Use the private reporting process in [SECURITY.md](SECURITY.md) for vulnerabilities or credential exposure. Do not report exploitable details in a public issue.
